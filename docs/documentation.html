1. Présentation générale

1.1 Objectif de l'application

ToolMap est une application web complète de gestion d'inventaire conçue pour un garage ou atelier. Elle répond aux besoins suivants :

  • Inventaire complet : gérer des Outils, Matériels et Consommables avec photos, catégories et descriptions
  • Localisation physique : situer chaque objet via un système de coordonnées à 4 niveaux (Lieu → Emplacement → Ligne → Colonne)
  • Plan 2D interactif : visualiser l'organisation des casiers sur une grille CSS Grid
  • Traçabilité totale : historique automatique de chaque mouvement (ajout, modification, suppression, prêt, retour, vente, épuisement)
  • Gestion des prêts : suivi des emprunteurs, dates prévues, retards
  • Gestion des stocks : seuil de stock minimum pour les consommables avec alertes visuelles
  • Tableau de bord : statistiques, graphiques camembert (Top 5), alertes stocks bas et prêts en retard
  • Export CSV : extraction des historiques au format tableur
  • Sauvegarde / Restauration : backup et restore complet de la base de données en JSON (jusqu'à 1 Go)
  • Thème clair / sombre : basculement instantané avec persistance
  • Design responsive : interface adaptée mobile, tablette et bureau

1.3 Système de coordonnées

Chaque emplacement physique est identifié par 4 niveaux hiérarchiques :

NiveauFormatExemplesDescription
LieuTexte libreGrange, Garage, Cabane_jardinBâtiment ou zone (gérable dynamiquement)
EmplacementE + numéroE0, E1, E11, E999Meuble / étagère dans le lieu
LigneLettre A-ZA, B, C, ... ZRangée verticale (max 26)
ColonneChiffre 1-N1, 2, 3, ... 50Position horizontale

Exemple complet : Garage - E11-B4 = Bâtiment Garage, meuble E11, rangée B, case 4.

MySQL config : Le paramètre max_allowed_packet=64M est configuré pour supporter les photos encodées en base64 et les sauvegardes volumineuses.

Dockerfile — Build multi-stage

StageBaseActions
basenode:20-alpineInstall dépendances, copie schema Prisma, npm install, prisma generate, next build (output: standalone)
runnernode:20-alpineCopie du build standalone, renommage server.js → server.standalone.js, ajout du wrapper HTTPS

Serveur HTTPS (server.js)

Le serveur de production fonctionne en deux couches :

  1. Next.js standalone (server.standalone.js) : écoute en HTTP sur le port 3000 (interne)
  2. Reverse proxy HTTPS (server.js) : écoute sur le port 443 avec les certificats SSL, redirige vers le port 3000

En cas d'erreur de proxy, le serveur retourne une 502 Bad Gateway.

3.2 Installation pas à pas

1
Cloner le projet 
git clone <url-du-repo>
cd toolmap
2
Générer les certificats SSL 
chmod +x generate-ssl.sh
./generate-ssl.sh

Crée ssl/key.pem et ssl/cert.pem (certificat auto-signé, RSA 2048 bits, valide 365 jours, CN=localhost).

3
Construire et lancer les conteneurs 
docker compose up -d --build

Première exécution : ~2 minutes (téléchargement images + build). Le Dockerfile exécute automatiquement prisma db push au démarrage.

4
Insérer les catégories par défaut (optionnel) 
docker exec toolmap-web ./node_modules/.bin/tsx prisma/seed.ts
5
Accéder à l'application 
https://localhost:444
Note : Le navigateur affichera un avertissement car le certificat est auto-signé. Cliquez « Avancé » → « Continuer vers localhost ».

5. API REST

Toutes les routes API se trouvent sous /api/. Les réponses sont au format JSON. Les erreurs retournent un objet { "error": "message" } avec le code HTTP correspondant.

5.1 Items

GET /api/items

Liste les items avec filtrage.

ParamètreTypeObligatoireDescription
referencestringNonFiltre par type (Outils, Materiels, Consommables)
categoryIdnumberNonFiltre par catégorie
searchstringNonRecherche dans le nom
statusstringNonFiltre par statut (défaut : "actif")
locationIdnumberNonFiltre par emplacement

Réponse : Tableau d'items avec category, location et nombre de prêts actifs (_count.loans). Trié par nom de catégorie puis nom d'item.

POST /api/items

Crée un nouvel item. Génère automatiquement un mouvement de type Ajout.

{
  "name": "Clé à molette 300mm",
  "reference": "Outils",
  "categoryId": 1,
  "quantity": 2,
  "unit": "unitaire",
  "locationId": 15,
  "description": "Clé ajustable chrome-vanadium",
  "photo": "data:image/jpeg;base64,...",
  "minStock": null
}

Réponse : 201 — Item créé avec relations.

GET /api/items/[id]

Détail complet d'un item incluant : catégorie, emplacement, historique des mouvements et prêts (triés par date décroissante).

PUT /api/items/[id]

Met à jour un item. Détecte automatiquement les changements et génère les mouvements correspondants :

  • Changement de statut → mouvement Vendu, Vide ou Reappro
  • Autres changements → mouvement Modif avec description détaillée

DELETE /api/items/[id]

Supprime un item. Génère un mouvement Suppression avant la suppression physique de l'enregistrement.

5.2 Catégories

GET /api/categories

Liste les catégories avec le nombre d'items associés. Filtre optionnel par reference.

POST /api/categories

{ "name": "Limes", "reference": "Outils" }

Réponse : 201 — Catégorie créée.

PUT /api/categories/[id]

Modifie le nom et/ou la référence d'une catégorie.

DELETE /api/categories/[id]

Supprime une catégorie. Échoue si des items y sont encore rattachés.

5.3 Lieux

GET /api/lieux

Liste tous les lieux, triés par nom.

POST /api/lieux

{ "name": "Atelier" }

Validations : nom non vide, pas de doublon (insensible à la casse).

Réponse : 201 — Lieu créé.

PUT /api/lieux/[id]

Renomme un lieu. Cascade automatique : met à jour le champ lieu dans toutes les tables Location et GridConfig associées.

DELETE /api/lieux/[id]

Supprime un lieu. Échoue (400) si des emplacements (Location) référencent encore ce lieu.

5.4 Emplacements & Grilles

GET /api/locations

Liste les emplacements avec le nombre d'items. Filtres optionnels : lieu, emplacement.

POST /api/locations

{ "lieu": "Garage", "emplacement": "E1", "ligne": "A", "colonne": 3 }

PUT /api/locations/[id]

Modifie un emplacement.

DELETE /api/locations/[id]

Échoue (400) si des items sont assignés à cet emplacement.

GET /api/grid

Liste les configurations de grille. Filtre optionnel par lieu.

POST /api/grid

Crée ou met à jour une grille (upsert sur lieu + emplacement). Génère automatiquement toutes les cases Location correspondantes (lignes A→Z, colonnes 1→N).

{ "lieu": "Garage", "emplacement": "E1", "rows": 4, "cols": 6 }

PUT /api/grid/[id]

Redimensionne une grille. Supprime les cases vides hors limites et détache les items des cases supprimées (locationId → null). Crée les nouvelles cases si la grille est agrandie.

DELETE /api/grid/[id]

Supprime une grille entière : détache tous les items et supprime toutes les cases Location associées.

5.5 Mouvements & Export CSV

GET /api/movements

Historique des mouvements avec filtrage.

ParamètreTypeDescription
typestringFiltre par type de mouvement
searchstringRecherche dans la description, le nom de l'item ou le type
hiddenbooleanSi true, filtre les types Vendu/Vide uniquement

Limite : 500 enregistrements maximum, triés par date décroissante.

GET /api/movements/export

Exporte les mouvements au format CSV (encodage UTF-8 avec BOM).

ParamètreTypeDescription
referencestringFiltre par type d'item
hiddenbooleanInclure uniquement les items masqués (vendu/vide)

Colonnes CSV : Date, Article, Référence, Type, Description, Statut.

5.6 Prêts

GET /api/loans

Liste des prêts. Filtre optionnel par status (en_cours, rendu).

POST /api/loans

{
  "itemId": 42,
  "firstName": "Jean",
  "lastName": "Dupont",
  "expectedReturn": "2026-05-15"
}

Génère automatiquement un mouvement de type Pret.

PUT /api/loans/[id]

{ "status": "rendu" }

Passe le prêt en statut "rendu", enregistre la date de retour effective (actualReturn) et génère un mouvement Rendu.

5.7 Dashboard

GET /api/dashboard

Retourne les données agrégées du tableau de bord :

ChampDescription

topOutilsTop 5 des outils les plus utilisés (par nombre de mouvements)
topConsommablesTop 5 des consommables les plus utilisés

lowStockConsommablesConsommables dont la quantité ≤ stock minimum

5.8 Sauvegarde & Restauration

GET /api/backup

Exporte l'intégralité de la base de données en JSON. Le fichier contient :

  • version : "1.0"
  • exportedAt : timestamp ISO 8601
  • categories, lieux, locations, gridConfigs, items, movements, loans

Le fichier est téléchargé automatiquement via Content-Disposition: attachment.

POST /api/backup

Restaure la base de données depuis un fichier JSON. Opération destructive :

  1. Validation du format du fichier
  2. Suppression de toutes les données existantes (dans l'ordre des dépendances)
  3. Restauration dans l'ordre inverse (avec conservation des identifiants)
Attention : La restauration écrase toutes les données existantes. Taille maximale acceptée : 1 Go (configuré dans next.config.ts via serverActions.bodySizeLimit).

7.4 Modification et suppression de grille

Redimensionnement

  • Ouvrir la modale d'édition d'une grille existante
  • Modifier le nombre de lignes et/ou colonnes
  • Les cases vides hors des nouvelles limites sont supprimées
  • Les items situés dans des cases supprimées sont détachés (locationId → null)
  • Les nouvelles cases (si agrandissement) sont créées automatiquement

Suppression

  • Confirmation requise avant suppression
  • Tous les items sont détachés (locationId → null)
  • Toutes les cases Location et la GridConfig sont supprimées

8. Système d'historique

8.1 Génération automatique

Chaque action significative sur un item génère automatiquement un enregistrement dans la table Movement. Le système construit des descriptions détaillées :

  • Ajout : « Article ajouté à l'inventaire »
  • Modification : description incluant chaque champ modifié (ex. : « Quantité : 5 → 3, Catégorie : Clés → Tournevis »)
  • Suppression : « Article supprimé de l'inventaire »
  • Prêt / Retour : identité de l'emprunteur et date de retour prévue
  • Statut : « Article marqué comme vendu/épuisé » ou « Réapprovisionné à X unité(s) »

8.2 Consultation et filtrage

Le composant MovementLog propose deux vues :

VueContenu
Historique des mouvementsTous les mouvements actifs (Ajout, Modif, Suppression, Pret, Rendu)
Historique masquéItems vendus ou épuisés (types Vendu, Vide)

Chaque vue inclut :

  • Recherche textuelle
  • Affichage chronologique avec horodatage, nom de l'item, badge de type coloré et description
  • Bouton « Réapprovisionné » dans l'historique masqué pour remettre un item en service avec une nouvelle quantité

8.3 Export CSV

Chaque vue d'historique dispose d'un bouton d'export CSV. Le fichier généré contient :

9. Gestion des prêts

9.1 Création d'un prêt

Depuis la fiche détail d'un item (ItemDetailModal) :

  1. Cliquer sur le bouton « Prêter »
  2. Remplir le formulaire : prénom, nom, date de retour prévue
  3. Valider → le prêt est créé avec le statut en_cours
  4. Un mouvement Pret est enregistré automatiquement

9.2 Retour d'un prêt

  1. Dans la fiche détail, les prêts actifs sont affichés avec un bouton « Retour »
  2. Cliquer sur « Retour » → le statut passe à rendu
  3. La date de retour effective (actualReturn) est enregistrée
  4. Un mouvement Rendu est généré

9.3 Alertes de retard

Le tableau de bord affiche les prêts en cours. Si la date de retour prévue est dépassée, un indicateur ⚠️ En retard apparaît dans la colonne statut.

10. Gestion des stocks (Consommables)

10.1 Stock minimum

Chaque consommable peut avoir un seuil de stock minimum (minStock). Ce champ est configurable :

  • À la création via le formulaire ItemForm (champ visible uniquement pour la référence Consommables)
  • Depuis la fiche détail (ItemDetailModal) avec édition inline

10.2 Alertes de stock bas

Le Dashboard affiche une carte d'alerte rouge lorsque des consommables ont une quantité inférieure ou égale au stock minimum :

10.3 Réapprovisionnement

Deux méthodes pour réapprovisionner un consommable :

  • Fiche détail : boutons +/- pour ajuster la quantité directement
  • Historique masqué : bouton « Réapprovisionné » pour remettre un item épuisé en service avec une nouvelle quantité (repasse le statut à actif et génère un mouvement Reappro)

11. Sauvegarde et restauration

Le composant BackupRestore (onglet « Sauvegarde » du paramétrage) permet :

Sauvegarde (Export)

  • Cliquer sur « Télécharger la sauvegarde »
  • Un fichier JSON est téléchargé contenant l'intégralité de la base
  • Format : version 1.0, timestamp d'export, toutes les tables

Restauration (Import)

  • Cliquer sur « Restaurer depuis un fichier »
  • Sélectionner un fichier .json précédemment exporté
  • Boîte de dialogue de confirmation (avertissement de perte de données)
  • Processus : validation du format → suppression → restauration → message de succès
Taille maximale : 1 Go. Ce paramètre est configuré dans next.config.ts via experimental.serverActions.bodySizeLimit. Pour les bases volumineuses (nombreuses photos en base64), vérifiez que cette limite est suffisante.

12.1 Mode clair / sombre

D. Format des photos

  • Stockage : les photos sont encodées en Base64 et stockées dans le champ photo (type LONGTEXT MySQL)
  • Format : la chaîne inclut le préfixe MIME (ex. : data:image/jpeg;base64,...)
  • Upload : via <input type="file" accept="image/*"> dans ItemForm, conversion en base64 côté client
  • Affichage : miniature dans la grille d'items, zoom plein écran via ImageZoom
  • Modification : ajout, remplacement et suppression de photo depuis ItemDetailModal
  • Limite MySQL : max_allowed_packet=64M dans docker-compose pour supporter les images volumineuses

E. Sécurité

  • HTTPS : toutes les communications sont chiffrées via TLS
  • Pas d'authentification : l'application est conçue pour un usage local/intranet. Aucun système de login n'est implémenté.
  • Injection SQL : Prisma ORM paramètre toutes les requêtes, éliminant les risques d'injection
  • XSS : React échappe automatiquement les contenus affichés dans le DOM
  • Mots de passe : les identifiants par défaut (MySQL) doivent être changés en production
  • Certificats : remplacer les certificats auto-signés par des certificats valides (Let's Encrypt) en production
  • NODE_TLS_REJECT_UNAUTHORIZED : défini à 0 pour le développement, à supprimer en production avec de vrais certificats
Recommandations production :
  • Changer tous les mots de passe par défaut
  • Utiliser des certificats SSL valides
  • Restreindre l'accès réseau (firewall, VPN)
  • Sauvegarder régulièrement la base de données
  • Ajouter une couche d'authentification si exposé sur Internet

F. Dépannage

ProblèmeCause probableSolution
Page blanche au lancement La base MySQL n'est pas prête Vérifier docker compose logs db. Attendre le healthcheck ou relancer docker compose restart web.
Erreur « Connection refused » Le conteneur web ne peut pas joindre MySQL Vérifier que le service db est healthy : docker compose ps. Vérifier le DATABASE_URL.
Certificat SSL invalide Certificats non générés ou expirés Exécuter ./generate-ssl.sh et relancer les conteneurs.
Erreur « Packet too large » Photo ou backup trop volumineux Vérifier max_allowed_packet dans docker-compose (64M par défaut). Augmenter si nécessaire.
Restauration échoue Format JSON invalide ou taille > 1 Go Vérifier le fichier JSON. Augmenter bodySizeLimit dans next.config.ts si nécessaire.
Schéma non à jour Modèle Prisma modifié sans migration Exécuter docker exec toolmap-web npx prisma db push
Items disparus après redimensionnement de grille Items détachés des cases supprimées Les items sont toujours présents mais sans emplacement (locationId = null). Réassigner manuellement.
Thème ne change pas Cache localStorage Vider le localStorage du navigateur (clé toolmap-theme) et recharger.
