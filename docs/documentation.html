1. Présentation générale

1.1 Objectif de l'application

ToolMap est une application web complète de gestion d'inventaire conçue pour un garage automobile. Elle répond aux besoins suivants :

  • Inventaire complet : gérer des Outils, Matériels et Consommables avec photos, catégories et descriptions
  • Localisation physique : situer chaque objet via un système de coordonnées 4 niveaux (Lieu → Emplacement → Ligne → Colonne)
  • Plan 2D interactif : visualiser l'organisation des casiers sur une grille CSS Grid
  • Traçabilité totale : historique automatique de chaque mouvement (ajout, modification, suppression, prêt, retour, vente, épuisement)
  • Gestion des prêts : suivi des clients, dates prévues, retards
  • Tableau de bord : statistiques et graphiques camembert (Top 10)
  • Export CSV : extraction des historiques au format tableur
  • Sauvegarde / Restauration : backup et restore complet de la base de données en JSON

1.3 Système de coordonnées

Chaque emplacement physique est identifié par 4 niveaux hiérarchiques :

NiveauFormatExemplesDescription
LieuTexte prédéfiniGrange, Grange_etage, Garage, Cabane_jardinBâtiment ou zone
EmplacementE + numéroE0, E1, E11, E999Meuble / étagère dans le lieu
LigneLettre A-ZA, B, C, ... ZRangée verticale (max 26)
ColonneChiffre 1-N1, 2, 3, ... 50Position horizontale

Exemple complet : Garage - E11-B4 = Bâtiment Garage, meuble E11, rangée B, case 4.

3.2 Installation pas à pas

1
Générer les certificats SSL 
cd toolmap
chmod +x generate-ssl.sh
./generate-ssl.sh

Crée ssl/key.pem et ssl/cert.pem (certificat auto-signé, valide 365 jours).

2
Construire et lancer les conteneurs 
docker compose up -d --build

Première exécution : ~2 minutes (téléchargement images + build).

3
Initialiser la base de données 
# Appliquer le schéma
docker exec toolmap-web ./node_modules/.bin/prisma db push

# Insérer les catégories par défaut
docker exec toolmap-web ./node_modules/.bin/tsx prisma/seed.ts
4
Accéder à l'application 
https://localhost
Note : Le navigateur affichera un avertissement car le certificat est auto-signé. Cliquez « Avancé » → « Continuer vers localhost ».

5. API REST

Toutes les routes sont sous /api/. Le format d'échange est JSON sauf pour l'export CSV.

5.1 Catégories /api/categories

MéthodeRouteParamètresDescription
GET/api/categories?reference=OutilsLister (avec compteur items)
POST/api/categoriesBody: {name, reference}Créer une catégorie
PUT/api/categories/:idBody: {name, reference}Modifier
DELETE/api/categories/:id—Supprimer

5.2 Items /api/items

MéthodeRouteParamètresDescription
GET/api/items?reference=&categoryId=&search=&status=&locationId=Lister (dédupliqué par ID)
POST/api/itemsBody completCréer + mouvement « Ajout » auto
GET/api/items/:id—Détail avec historique et prêts
PUT/api/items/:idBody partielModifier + mouvement « Modif » auto
DELETE/api/items/:id—Supprimer + mouvement « Suppression » auto
Paramètre status : actif (défaut) = items actifs ; hidden = items vendu/vide (historique masqué).

5.3 Emplacements & Grilles

MéthodeRouteDescription
GET/api/locations?lieu=GarageLister les emplacements (avec compteur items)
POST/api/locationsCréer un emplacement unitaire
GET/api/grid?lieu=GarageLister les configurations de grille
POST/api/gridGénérer une grille (upsert config + création locations)
PUT/api/grid/:idModifier dimensions (détache items hors grille)
DELETE/api/grid/:idSupprimer plan + détacher tous les items
Comportement à la suppression/réduction : Les items dans les casiers supprimés sont automatiquement détachés (locationId = null). Aucun item n'est perdu.

Historique des mouvements

  • Historique des mouvements : tous les mouvements filtrables + Export CSV

7. Plan 2D des casiers

7.1 Génération de grille

Processus de création d'un plan :

  1. Sélectionner le Lieu (menu déroulant : Grange, Grange_etage, Garage, Cabane_jardin)
  2. Saisir l'Emplacement (E0, E1, E11...)
  3. Définir le nombre de lignes (1 à 26 → A à Z)
  4. Définir le nombre de colonnes (1 à 50)
  5. Cliquer « Générer le plan »

L'API crée automatiquement une GridConfig et toutes les Location correspondantes via upsert.

7.3 Interaction avec un casier

Au clic sur une case, un modal s'ouvre avec :

  • Titre : nom complet du casier (ex: « Garage — E0-B4 »)
  • Liste des items présents : miniature photo, nom, catégorie, quantité, unité
  • Bouton « + Ajouter un élément » : ouvre un formulaire ItemForm avec l'emplacement pré-rempli

7.4 Modification et suppression

Chaque plan affiché dispose de deux boutons en haut à droite :

Bouton « Modifier »

  • Ouvre un modal avec les dimensions actuelles (lignes / colonnes)
  • Le lieu et l'emplacement sont affichés en lecture seule
  • Si la grille est réduite : les items dans les casiers supprimés sont détachés (emplacement remis à vide)
  • Si la grille est agrandie : de nouvelles locations sont créées

Bouton « Supprimer »

  • Demande confirmation
  • Détache tous les items de la grille (locationId = null)
  • Supprime toutes les locations et la configuration du plan
  • Aucun item n'est perdu : ils passent simplement en « non assigné »

8. Système d'historique

8.1 Génération automatique

Chaque changement d'état génère automatiquement une entrée dans la table Movement :

Action utilisateurType mouvementDescription générée automatiquement
Création d'itemAjout« Ajout de "Nom" (Réf) »
Modification de champsModifDétail des champs modifiés (Nom: X → Y, Quantité: 5 → 3)
Suppression d'itemSuppression« Suppression de "Nom" »
Création de prêtPret« Prêt à Prénom Nom - retour prévu le JJ/MM/AAAA »
Retour de prêtRendu« Retour de prêt par Prénom Nom »
Marquage « Vendu »Vendu« Statut changé vers "vendu" »
Marquage « Vide »Vide« Statut changé vers "vide" »

8.2 Consultation et filtrage

Deux journaux accessibles depuis chaque page (Outils, Matériels, Consommables) via des boutons sous la liste :

  • Historique des mouvements : tous les mouvements, filtrable par recherche texte libre
  • Historique masqué (Vendu/Vide) : uniquement les mouvements de type Vendu et Vide

Chaque entrée affiche : date, nom de l'article, badge coloré du type, description.

8.3 Export CSV

Chaque modal d'historique dispose d'un bouton « Exporter CSV » qui :

  • Télécharge un fichier .csv encodé en UTF-8 avec BOM (compatible Excel)
  • Colonnes : Date, Article, Reference, Type, Description, Statut
  • Filtre automatiquement par la référence de l'onglet courant (Outils, Materiels, Consommables)
  • Nom du fichier : historique_Outils_mouvements.csv ou historique_Outils_masque.csv

9. Gestion des prêts

Création d'un prêt

  1. Ouvrir la fiche détail d'un item actif
  2. Cliquer « Prêter »
  3. Remplir : Prénom, Nom, Date de retour prévue
  4. Valider → mouvement Pret généré automatiquement

Retour d'un prêt

  1. Ouvrir la fiche détail de l'item
  2. Dans « Prêts en cours », cliquer « Rendu »
  3. Statut → rendu, date de retour effectif enregistrée, mouvement Rendu créé

Suivi sur le Dashboard

Tableau central listant tous les prêts actifs. Les retours en retard sont signalés en rouge avec ⚠.

10. Sauvegarde et restauration

Accessible dans Paramétrage → onglet « Sauvegarde / Restauration ».

Sauvegarde (Export)

  • Bouton « Télécharger la sauvegarde »
  • Exporte l'intégralité de la base (6 tables) dans un fichier JSON
  • Nom : toolmap_backup_2026-04-08.json
  • Inclut : categories, items (avec photos Base64), locations, gridConfigs, movements, loans

Restauration (Import)

  • Bouton « Restaurer depuis un fichier » (rouge, indique le danger)
  • Demande de confirmation avant exécution
  • Processus :
    1. Suppression de toutes les données existantes (dans l'ordre des dépendances)
    2. Insertion des données du fichier (dans l'ordre des dépendances)
    3. Conservation des IDs originaux
  • Message de succès ou d'erreur affiché
Précaution : Toujours effectuer une sauvegarde avant toute restauration. L'opération est irréversible.
