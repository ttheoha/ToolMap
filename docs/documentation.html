1. Présentation générale

1.1 Objectif

ToolMap est une application web de gestion d'inventaire conçue pour un garage automobile. Elle permet de :

  • Gérer un inventaire complet d'Outils, Matériels et Consommables
  • Localiser physiquement chaque objet via un système de coordonnées (Lieu, Emplacement, Ligne, Colonne)
  • Visualiser les emplacements sur un plan 2D interactif
  • Suivre l'historique complet de chaque mouvement
  • Gérer les prêts de matériel avec suivi client
  • Afficher un tableau de bord avec statistiques et graphiques

3. Installation et déploiement

3.1 Prérequis

  • Docker (version 20+) et Docker Compose (v2+)
  • OpenSSL (pour la génération des certificats SSL)

3.2 Étapes d'installation

Étape 1 : Générer les certificats SSL

cd toolmap
chmod +x generate-ssl.sh
./generate-ssl.sh

Cela crée ssl/key.pem et ssl/cert.pem (certificat auto-signé, valide 365 jours).

Étape 2 : Lancer les services

docker compose up -d --build

Cela démarre :

  • toolmap-db : MySQL 8.0 sur le port 3306
  • toolmap-web : Next.js en HTTPS sur le port 443

Étape 3 : Initialiser la base de données

# Appliquer le schéma Prisma
docker exec toolmap-web npx prisma db push

# Exécuter le seed (catégories par défaut)
docker exec toolmap-web npx prisma db seed

Étape 4 : Accéder à l'application

https://localhost
Note : Le navigateur affichera un avertissement de sécurité car le certificat est auto-signé. Cliquez sur « Avancé » → « Continuer » pour accéder au site.

5. API REST — Routes

5.1 Catégories

MéthodeRouteDescription
GET/api/categories?reference=OutilsLister les catégories (filtre optionnel)
POST/api/categoriesCréer une catégorie
PUT/api/categories/:idModifier une catégorie
DELETE/api/categories/:idSupprimer une catégorie

5.2 Items

MéthodeRouteDescription
GET/api/items?reference=Outils&status=actif&search=clé&categoryId=1Lister les items (multiples filtres)
POST/api/itemsCréer un item (+ mouvement «Ajout» auto)
GET/api/items/:idDétail d'un item avec historique et prêts
PUT/api/items/:idModifier un item (+ mouvement «Modif» auto)
DELETE/api/items/:idSupprimer un item (+ mouvement «Suppression» auto)
Déduplication : Le endpoint GET /api/items déduplique automatiquement les résultats par ID pour éviter les doublons.

Paramètre status

  • actif (défaut) : Items actifs uniquement
  • hidden : Items «vendu» ou «vide» (historique masqué)

Composant modal générique avec overlay, fermeture par Escape ou clic extérieur. Tailles : sm, md, lg, xl.

Affiche une miniature 64x64. Au clic, ouvre l'image en plein écran dans un overlay noir.

ItemForm

Formulaire de création/édition d'un item. Champs : Nom, Catégorie, Emplacement, Quantité, Unité, Description, Photo (upload fichier → Base64).

ItemListPage

Composant principal de liste utilisé par les 3 pages (Outils, Matériels, Consommables). Fonctionnalités :

  • Barre de recherche globale (nom, catégorie, référence)
  • Filtre par catégorie
  • Affichage en grille responsive (1 à 4 colonnes)
  • Miniatures cliquables avec zoom
  • Actions : modifier, supprimer (au survol)
  • Clic sur une carte → modal détail

ItemDetailModal

Fiche détail complète d'un item incluant :

  • Photo, tags (référence, catégorie, statut)
  • Informations : quantité, unité, emplacement
  • Boutons d'action contextuel selon le type :
    • Prêter : disponible pour tous les types actifs
    • Vendu : uniquement pour les Matériels
    • Vide : uniquement pour les Consommables
  • Formulaire de prêt intégré
  • Liste des prêts en cours avec bouton «Rendu»
  • Historique complet des mouvements

MovementLog

Deux boutons ouvrant chacun un modal :

  • Historique des mouvements : tous les mouvements filtrables
  • Historique masqué : uniquement les mouvements de type «Vendu» et «Vide»

7. Plan 2D des casiers

7.1 Principe

Le plan 2D permet de visualiser l'organisation physique du stockage dans chaque lieu. Il est accessible depuis la page Paramétrage.

7.2 Configuration

  1. Sélectionner le lieu via le menu déroulant
  2. Définir l'emplacement (E0, E1, E11...)
  3. Nombre de lignes (1 à 26 → A à Z)
  4. Nombre de colonnes (1 à 50)
  5. Cliquer Générer le plan

7.3 Affichage de la grille

La grille est rendue en CSS Grid avec :

  • En-têtes de colonnes (1, 2, 3...) alignés en haut
  • En-têtes de lignes (A, B, C...) alignés à gauche
  • Chaque cellule affiche son identifiant (ex: E0-A1)

Deux journaux accessibles depuis chaque page (Outils, Matériels, Consommables) :

  • Historique des mouvements : tous les mouvements, filtrable par recherche texte
  • Historique masqué : mouvements de type «Vendu» et «Vide» uniquement

9. Gestion des prêts

9.1 Création d'un prêt

  1. Ouvrir la fiche détail d'un item actif
  2. Cliquer «Prêter»
  3. Remplir : Prénom, Nom, Date de retour prévue
  4. Valider → un mouvement «Pret» est automatiquement créé

9.2 Retour d'un prêt

  1. Ouvrir la fiche détail de l'item concerné
  2. Dans la section «Prêts en cours», cliquer «Rendu»
  3. Le statut passe à «rendu» et la date de retour effectif est enregistrée
  4. Un mouvement «Rendu» est automatiquement créé

9.3 Suivi sur le Dashboard

Le tableau de bord affiche en temps réel la liste des prêts en cours avec :

  • Nom/Prénom du client
  • Article prêté et son type
  • Date du prêt et date de retour prévue
  • Indicateur visuel si le retour est en retard (texte rouge + ⚠️)

12.2 Dockerfile (multi-stage)

  1. Stage base : Install des dépendances, génération Prisma, build Next.js
  2. Stage runner : Copie du build standalone, certificats SSL, serveur custom

12.3 Serveur HTTPS (server.js)

Serveur Node.js custom utilisant le module https natif avec les certificats SSL générés. Next.js est utilisé en mode programmatique.

12.4 Healthcheck MySQL

Le service MySQL inclut un healthcheck (mysqladmin ping) toutes les 10 secondes. Le service web attend que MySQL soit healthy avant de démarrer.

12.5 Volume persistant

Le volume mysql_data assure la persistance des données MySQL entre les redémarrages.

Annexe B : Format des données photo

Les photos sont stockées en base de données sous forme de chaîne Base64 complète incluant le préfixe MIME :

data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAA...

Taille maximale : définie par max_allowed_packet=64M dans MySQL et bodySizeLimit: "10mb" dans Next.js.

Annexe E : Sécurité

  • HTTPS obligatoire (port 443)
  • Certificat SSL (auto-signé en dév, Let's Encrypt recommandé en prod)
  • Mot de passe MySQL configurable via variables d'environnement
  • Prisma ORM protège contre les injections SQL
  • Upload photo limité à 10 MB
  • Pas d'authentification utilisateur (application locale/intranet)
Recommandation production : Ajouter une couche d'authentification (NextAuth.js) si l'application est exposée sur Internet.
